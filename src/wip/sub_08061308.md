## Role

CpuSet fill using sprite byte unk5D as VRAM bank.

## Process

- C already emits `ldrb r1,[r0]; lsls r1,r1,#0x0E` vs retail `ldrb r0,[r0]; lsls r1,r0,#0x0E`
  (same 2-byte regalloc gap as siblings `sub_0806184C`, `sub_08061800`, `sub_08061BE8`,
  `sub_0806114C`, `sub_08060D58`, `sub_08060E48` — all parked as readable Thumb).
- 2026-09-21 — exhaustive retry. ~60 source variants + 240 declaration-order permutations
  + 2 decomp-permuter runs (15k iterations each, base score 10, never below 10).
- All variants land on one of two 46/48 attractors:
  - `u16 tmp` (seed) → first load wrong (`ldrb r1,[r0]`, coalesced load+shift), second correct.
  - `u32 tmp` reused for both fields → first load correct (`ldrb r0,[r0]; lsls r1,r0`), second
    wrong (`ldrh r0,[r2]; lsls r2,r0,#5` vs retail `ldrh r2,[r2]; lsls r2,r2,#5`).
- Type/order/reuse experiments tried and rejected: `u32`/`u8`/`u16` temps, two separate temps
  (u32+u16, u16+u32, u32+u32), declaration-with-initializer forms, `VRAM` macro vs `0xC0u << 19`,
  `* 32` / `* 0x4000` strength-reduction forms, `dst` as `void *`/`u8 *`/`u32`, volatile reads,
  volatile `s`, `&s->unk5D` pointer reads, inline `n` in the call, reordered statements,
  declaration permutations. None reach 48/48.
- Mechanism: retail needs the first bank byte to be *non*-coalesced with its shift (load → r0,
  shift → r1) while the second value *is* coalesced with `n` (load+shift → r2). agbcc gives one
  or the other depending on whether the temp has two live ranges, never both.
