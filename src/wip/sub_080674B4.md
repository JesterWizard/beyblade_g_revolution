## Role

BIOS `swi 5` (CpuSet) trampoline: sets r2 = 0 and leaves r0/r1 as the caller passed them.

## Process

- 2026-09-20 — parked. Status: matched only with GCC asm labels; stripped DIFF
- 2026-09-21 — **solved**. `asm("swi 5" : : "r"(src), "r"(dest), "r"(0))` with two
  pass-through parameters gives exactly `movs r2,#0; swi 5; bx lr`. Notes on the dead ends:
  - `void sub_080674B4(void) { asm("movs r2, #0\n\tswi #5"); }` — rejected by the
    semantic-asm policy (`match_function.py` only allows bare `swi`).
  - `void sub_080674B4(const void *src, void *dest) { CpuSet(src, dest, 0); }` emits
    `bl CpuSet` (12 bytes: push/bl/pop) instead of the inline `swi`, because this repo's
    `gba/syscall.h` declares `CpuSet` as a real function.
  - The header prototype is `void sub_080674B4(void);`, so a 2-arg definition conflicts;
    making it 2-arg in `include/unknown-functions.h` breaks the C callers
    (`src/matched/sub_08048D0C.c`, 4 WIP seeds) that call it with no arguments.
  - `asm("swi 5" : : "r"(0))` is policy-legal but lets the allocator pick r0, not r2.
  - The permuter's score-0 hit was a branch-target false zero (verified 5/6).
