## 2026-09-21 — matched (semantic C)

Landed as semantic C in `src/matched/sub_08062A74.c` at 76/76 by using
**`/* match-compiler: old_agbcc */`**. The older compiler allocates the shift/`ldrh`
pair differently from `agbcc`, so the body that was stuck at 74/76 reaches retail
once the palette constant is written twice and the OBJ-PAL offset is folded into
one add:

```
r2 = 0x080BB8C0;
r2 = 0x080BB8C0;
r1 = (r4 << 5) + 0x05000200;
```

`agbcc` still emits `lsls r3` for that shape; `old_agbcc` emits the retail
`lsls r1` while keeping the handler pool in `r2`. See
[`docs/decomp-status.md`](../../docs/decomp-status.md) for the compiler split.

## Earlier retries (agbcc only — superseded)

- ~2,500 enumerated variants around the palette region: shift target r1/r2/r3, inner
  assignment target, copy vs direct vs expression-inline vs reordered, table-pointer
  register, table-value register, constant typing, declaration-order shuffles.
- Both allowed match-flags — no change.
- 20 min / 8 jobs of `permuter/auto.py` — base score 10, never below 10.

Two attractors, mutually exclusive under `agbcc`:

| form | `ldrh` dest | `lsls` dest | score |
|------|-------------|-------------|------:|
| seed `r1 = (r3 = r4 << 5)` | `r2` ✓ | `r3` ✗ (want r1) | 74/76 |
| plain `r1 = r4 << 5` | `r3` ✗ (want r2) | `r1` ✓ | 72/76 |

The seed's nested assignment is what keeps `r3` reserved through the u16 block, which
forces `ldrh` into `r2` — and the same line is what makes the shift land in `r3`. The
plain form frees `r3` early, so the `ldrh` temp *and* the table pointer both fall into
`r3` and the shift is correct. No `agbcc` formulation kept both properties; the
two-fold constant write plus `old_agbcc` does.
